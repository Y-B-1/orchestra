Orchestra Routing Graph v2

Human view of .cursor/skills/orchestrator/flow.json, the only statement of routing. Every transition is announced in chat. Green blocks are standing duties that fire on every entry; red BACK TO rows are first-class backward edges with the payload that travels; pills name dispatched roles (with @L1..L3 depth). Verbatim rulings, evidence-gated DONE, and honest terminal states apply everywhere.

Roster (12 + the orchestrator)

orchestrator

Main session. Talks to you, dispatches everyone, adjudicates, merges, approves, owns memory.

scout read-only

Codebase recon: files, symbols, conventions, verified tooling commands, path-rule harvest.

researcher background

Primary sources only → cited RESEARCH.md with expiry.

architect docs only

Drafts approach sketches and the spec from settled verbatim rulings. Open decisions come back as questions, never choices.

planner docs only

Drafts and repairs the ticketed plan; red-team findings loop to it, rounds 1–3.

red-teamer read-only

One lens per dispatch: requirements · feasibility · scope · judge. First principles, reverse-engineered failure, interaction space weighted by probability.

builder

One ticket, TDD, assigned tree. Fresh per ticket. Trailer feeds the ledger.

builder-max ceiling tier

Escalation, findings round 4 only. Reads the failure history first.

reviewer read-only

Fresh eyes on one ticket's diff. Builder reports are never evidence.

auditor read-only

Whole change-set, one axis: Standards or Spec. Parallel, never merged.

gatekeeper

Runs the command list the orchestrator derived; honest exit codes at a named hash. Fixes nothing.

janitor

Worktree directory inspection, memory draft from the ledger excerpt, process-adherence checklist. Proposes only.

releaser

Draft PRs early; stages gated actions and pauses. The hook's user-facing ask is the floor; its block is the record.

Running in the cloud

topology

defaultone cloud agent IS the orchestrator; sub-agents run inside its VM sharing one clone — the whole chain applies unchanged, worktrees included
parallel independent workone cloud agent per feature/ticket, each running its own mini-chain and returning a PR. Split work across VMs, never roles — role handoffs would become git round-trips
alwaysonly committed things travel: a VM is a fresh clone, so gitignored files (including .orchestra/state.json) are absent
conversation neededa cloud orchestrator reaches you asynchronously — run design and plan locally, send execute waves to the cloud
enforcementask degrades to deny when headless; a protected landing with no readable gate record is denied; set server_side_gate so the host's branch policy is the gate — host-mediated PR completion stays allowed, direct pushes to protected branches never do

Invariants (every state)

  • Self-contained briefs: verbatim-critical excerpts pasted; bulk material as pointers the role reads itself.
  • Sub-agents never spawn sub-agents (hook-enforced policy); all fan-out is the orchestrator's.
  • Rulings travel verbatim: full quote only if one line, else pointer; never trimmed.
  • Evidence = command + exit code without pipes, or both-theme screenshots.
  • Worktrees only for 2+ concurrent builders; created, integrated, removed by the orchestrator.
  • Judgement roles at the ceiling (inherit); the rest pinned at install; install.sh verifies.
  • Approval floor is the hook's user-facing ask; files never authorize.
  • Memory lands in the batch-closing commit; stale entries are pruned.
  • Honest terminal states, always.
  • Every transition announced: flow: from → to (matched if).
