Use that provider's CLI (github: gh · azure-devops: az repos · gitlab: glab · plain-git: git). server_side_gate is true only when a host branch policy actually runs the fast set — do not infer it from an Azure remote URL alone.

The hook never returns ask (no human click). pr-reviewer CLEAN + matching last_green_hash allows land and declared deploys, including headless. Running in the cloud

topologyDEFAULT (A): one cloud agent IS the orchestrator; its sub-agents are children inside that same VM, sharing one clone. Everything in this graph applies unchanged. ALTERNATIVE (B): one cloud agent per independent FEATURE or ticket, each running its own mini-chain and returning a PR. Never split ROLES across VMs — roles are coupled by handoffs, and every boundary would become a git round-trip.
worktreesTopology A: sub-agents share the VM's single clone and single git index, so the local rule applies unchanged — 2+ concurrent builders get worktrees inside the VM. Topology B: each VM is already an isolated clone; no worktrees.
handoffTopology A: briefs + shared disk, as local. Topology B: nothing but git (pushed branches) and the orchestrator relaying report text — anything load-bearing must be committed, because gitignored files do not exist in a fresh clone.
conversationA cloud orchestrator cannot hold a live conversation; it reaches the user asynchronously (Slack, web, PR comments). Design and plan are conversations — run them locally. Execute waves are the natural cloud workload.
enforcementThe hook never returns ask. Headless land/deploy is allow when reviews.pr=CLEAN and gates.last_green_hash matches HEAD (write those in-session before the releaser). A fresh clone has no state.json — seed from docs/orchestra/state.example.json; a protected landing with no CLEAN+fresh record is DENIED. server_side_gate allows host-mediated PR completion. Hooks also do not run during a cloud agent's early read-only turns.
configRepo-level config travels with the clone (.claude/agents, .claude/skills, .claude/settings.json, .cursor/* for Cursor, AGENTS.md). User-level config (~/.cursor/*, ~/.claude/*) does NOT. Keep this package project-scoped.

Invariants

  • Sub-agent briefs are self-contained: verbatim-critical excerpts (rulings, done_when, path rules) pasted; bulk material passed as pointers the agent reads itself.
  • Sub-agents never spawn sub-agents, including more of their own role (policy; subagentStart hook denies it). All fan-out is the orchestrator's: N concurrent instances of one role per wave, as the plan names.
  • User rulings travel verbatim — full quote only when it fits one line, else pointer; never a trimmed quote.
  • Evidence = command + exit code (captured without pipes) or both-theme screenshots; assertions are not evidence.
  • Worktrees only for 2+ concurrent editors; created, integrated, and removed by the orchestrator within the wave.
  • Judgement roles (architect, planner, red-teamer, auditor, builder-max, pr-reviewer) run model: inherit — the ceiling; the rest are pinned lower at install (install.sh verifies).
  • Approval boundaries: destructive git is deny. The hook never returns ask. pr-reviewer CLEAN + matching last_green_hash is merge and deploy authorization (including headless). Without CLEAN, protected landings and declared deploys are deny. The only user-facing stop after intake is design.frontier for decisions the request did not settle. Specs, plans, reviews, merges, and deploys do not wait. Full e2e is never in the execute/review/release chain.
  • Memory lands in the batch-closing commit; stale entries are pruned, not superseded-in-place.
  • Honest terminal states — DONE, BLOCKED, NOT-READY, NEEDS-APPROVAL; never one dressed as another.
  • Every transition announced: `flow: <from> -> <to> (<matched if>)`.
